# 家里电脑常驻部署（第①步「自己用起来」）

家里一台 Windows 电脑一直开着跑 Noyi，手机经 Tailscale 访问。公司电脑发布新版本，家里自动升级，升级失败自动退回。运行日志（不含饮食、体重、照片和原话）每小时回传到私有仓库 `noyi-ops`。

## 布局

| 位置 | 内容 |
| --- | --- |
| `D:\Noyi\repo` | 公开仓库 noyi 的克隆，只用来取 `home-*` 标签 |
| `D:\Noyi\releases\<标签>` | 每个版本一个目录，各带自己的 `.venv` 和 Pi 依赖；只保留当前和上一版 |
| `D:\Noyi\data` | 账本、上传、日志、备份。固定不动，不在任何版本目录里 |
| `D:\Noyi\ops` | `noyi-ops` 的克隆，日志包写在这里再推送 |
| `D:\Noyi\bin` | 守护、升级、回传三个脚本；每次升级成功后用新版本的脚本替换 |
| `D:\Noyi\current.json` | 当前版本和上一版本 |
| `D:\Noyi\home.json` | 可选设置：端口、外网域名等 |

三个计划任务（`\Noyi\` 文件夹下）：

- **Service**：开机启动守护进程 `supervise.py`。服务崩溃后分别等 5 秒、30 秒、2 分钟再重启；同一版本 10 分钟内崩 5 次就停下，不再无限重启，等下一个版本。
- **Upgrade**：每 10 分钟检查一次新标签，过程见下节。
- **OpsPush**：每小时导出一份脱敏日志包，推到 `noyi-ops`。

任务以你的账号用 S4U 方式运行：不用登录桌面，也不保存 Windows 密码。代价是访问不了需要登录的网络共享盘，但 GitHub、DeepSeek、苹果推送这类 HTTPS 访问不受影响。

## 一次性安装（约 30 分钟）

1. 用「以管理员身份运行」打开 PowerShell，执行：

   ```powershell
   iwr https://raw.githubusercontent.com/BaoBao1996121/noyi/main/scripts/home/install.ps1 -OutFile $env:TEMP\noyi-install.ps1
   powershell -ExecutionPolicy Bypass -File $env:TEMP\noyi-install.ps1
   ```

   想先看它会做什么，在第二行末尾加 `-DryRun`：只打印步骤和计划任务命令，不做任何改动。
2. 按提示粘贴 DeepSeek 密钥。它会存成你账号的环境变量 `NOYI_DEEPSEEK_KEY`，不写进任何文件。家里默认使用 `deepseek-flash`，它能看图。
3. 脚本会打印一行部署公钥，并打开 `noyi-ops` 的 Deploy keys 页面。把公钥贴进去，勾选 **Allow write access**，保存后回到窗口按回车。
4. 最后的自检三项都显示 OK 才算装好：服务能打开、能从 GitHub 取更新、能往 `noyi-ops` 推送。
5. **重启电脑一次**，不登录，用手机或另一台电脑确认服务自己起来了。
6. 想停电恢复后自动开机：进 BIOS，打开「来电自动开机」（各厂商叫法不同，比如 Restore on AC Power Loss）。脚本做不了这一步。

脚本会把「接通电源时从不睡眠」打开。不想改电源设置，加 `-KeepPowerPlan`。重复运行安装脚本是安全的：已有的数据、密钥和版本都会保留。

## 手机访问（iPhone）

1. 家里电脑和 iPhone 都装 Tailscale，并登录同一个账号。iPhone 版要从 App Store 下载。国区 App Store 能不能搜到 Tailscale 还没核实，搜不到时需要用其他地区的 Apple ID。
2. 在 Tailscale 管理后台的 DNS 页面打开 MagicDNS 和 HTTPS Certificates。
3. 家里电脑在普通 PowerShell 里执行：

   ```powershell
   tailscale serve --bg 8765
   ```

   这条命令只在你的 tailnet 内部开放，不对公网开放，重启后依然有效。它会打印一个地址，类似 `https://noyi-home.tailxxxx.ts.net`。想关掉时执行 `tailscale serve --https=443 off`。
4. 把这个域名写进 `D:\Noyi\home.json`。保存后在 <http://127.0.0.1:8765> 用停止入口停一次服务，守护进程会带着新设置自动重新启动：

   ```json
   {"remote_hosts": ["noyi-home.tailxxxx.ts.net"]}
   ```

   不在这个名单里的地址一律拒绝访问。还可以加 `"remote_login": "你的 Tailscale 登录名"`，再核对 Tailscale 带过来的身份。
5. 在家里电脑上打开 <http://127.0.0.1:8765>，进入「设置 → 添加手机 → 生成配对码」。配对码 5 分钟内有效，只能用一次。
6. iPhone 用 Safari 打开那个 https 地址，输入配对码。接着点「分享 → 添加到主屏幕」，**从主屏幕图标打开**后，点页面上的「开启通知」。通知需要 iOS 16.4 或更高版本，并且只在从主屏幕打开时可用。

配对后的 iPhone 可以聊天、拍照记饭、看汇总；密钥设置、停止服务、备份、添加或移除设备只能在家里电脑上操作。手机丢了，在家里电脑的「添加手机」里点「移除」即可。

### 提醒和「送达」

- 推送只带一句固定的话（如「今晚的饮食汇总好了，点开查看」）和消息编号，饭菜、体重和回复原文不经过苹果的推送服务。
- 推送发出后，消息状态是「已推送」；**页面实际显示过**这条消息，才算送达，对应的承诺才算完成。
- 苹果可能延迟或丢弃推送（手机长时间没打开这个应用时更容易发生）。打开网页时，页面顶部会列出「推送到手机后还没看到」的提醒。
- 网页开着时不推送，直接显示在页面上。
- 「Tailscale 连接下推送能不能到达」要在家里装好后实测一次：开启通知后锁屏，等每晚汇总，或者在电脑上让助理设一个几分钟后的汇总时间。

## 升级怎么保证不坏库

公司电脑在 `main` 上打 `home-YYYYMMDD-N` 标签并推到 GitHub，家里的升级任务发现后：

1. 只接受指向 `origin/main` 上已有提交的标签；失败过的标签不再重试。
2. 在新目录检出、安装依赖、跑冒烟测试。
3. 用 SQLite 在线备份复制账本，并跑 `integrity_check`。
4. **彩排**：新版本在另一个端口打开这份副本（这一步会执行迁移），后台工作关闭，不调模型、不推送；页面必须正常响应。彩排失败就不切换，旧版本照常运行。
5. 切换：停掉旧服务（停止时会保存执行状态），再备份一次，然后让守护进程启动新版本。
6. 2 分钟内的健康检查不通过，就停掉新版本，**用第 5 步的备份恢复账本**，再退回旧版本。旧版本会拒绝打开更新过的账本，所以退回必须恢复账本，不能只换代码。从停服到退回之间写入的内容会丢，这段时间最多约 2 分钟，而且这段时间服务本来就没在正常工作。

结果写在 `D:\Noyi\upgrade.json`，也会随日志回传。账本备份在 `D:\Noyi\data\backups`，每类保留最近 10 份。

### 发布一个版本（公司电脑）

全量测试通过后：

```bash
git tag home-$(date +%Y%m%d)-1 && git push origin home-$(date +%Y%m%d)-1
```

同一天发第二个版本，序号加 1。家里最迟 10 分钟内开始升级。

### 手动操作

- 立即检查升级：`python D:\Noyi\bin\upgrade.py --root D:\Noyi`
- 暂停服务（比如要手动动库）：建一个空文件 `D:\Noyi\hold`，删掉后自动恢复。
- 手动退回上一版：停服务、从 `data\backups` 里选对应的 `switch-<标签>-*.sqlite` 覆盖 `data\state.sqlite`、把 `current.json` 的 `tag` 改成上一版本，再删掉 `hold`。

## 回传了什么

每小时一份 `bundles/日期/时间.json`，外加一份 `latest.json`。内容只有：错误类型和代码位置（不含错误信息）、每轮、每次模型调用和工具调用的耗时、token 与失败类型、升级与崩溃次数、磁盘余量、估算偏差（只有数字）、问题标记（分类，加上你在「这里不对」里确认可以回传的那句话）。

机制保证：导出器只读「列登记表」里登记为可导出的列，自由文本列不能登记为可导出；新增表或列没有登记，测试就会失败；健康表里的数字和每个文本列的特征串，都会在测试里检查是否出现在导出结果中；推送前按封闭结构校验，多出任何字段就不推送。

## 在公司电脑上测过什么

- `tests/test_home_upgrade.py` 用本地裸仓库代替 GitHub，用真实的守护和升级脚本跑完整演练：首次安装、正常升级，以及迁移失败、启动失败、健康检查失败三种失败情况，加上不在 `main` 上的标签。每种情况都断言账本内容和当前版本正确。另有一项测试守护进程的崩溃退避和崩溃循环停机。
- `--rehearsal` 模式在真实 Noyi 和演示库副本上验证过：页面能打开，停止入口能结束进程。
- 安装脚本只在公司电脑上做过 `-DryRun`；计划任务、S4U、开机自启、Tailscale 和苹果推送要在家里实测。
