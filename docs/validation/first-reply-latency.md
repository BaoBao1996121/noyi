# 首句回复延迟：分段耗时与根因（2026-11-16）

口径：自用库最近一段真实对话（公司电脑，DeepSeek flash 官方接口），从账本表 `conversation_inputs`、`runs`、`steps`、`model_requests`、`deliveries` 的时间戳逐条对齐；另在本机用库副本和同一份 Node 桥复测。只取时间，不取内容。

## 分段耗时（改前）

| 段 | 怎么量的 | 实测 |
|---|---|---|
| 网页提交 → 入库 | `accept_conversation` 在库副本上计时 | 约 4 毫秒 |
| 入库 → 被调度接手 | `runs.started − conversation_inputs.created` | 0.01～0.30 秒（调度空闲时每 0.3～0.5 秒轮询一次） |
| 接手 → 开始调模型 | `model_requests.created − steps(engine).created` | **中位 2.5 秒，最慢 10.4 秒**；当天 5 条为 3.3 / 4.7 / 7.6 / 8.6 / 10.4 秒 |
| 　其中：拼上下文、读记忆 | 库副本上 cProfile | 约 10 毫秒 |
| 　其中：启动 Node + 加载 Pi 包 | 在本机反复启动同一个桥 | 每次 1.2～2.1 秒；公司电脑更慢（杀毒逐个扫描约 3000 个 JS 文件） |
| 对话模型调用 | `model_requests.ended − created` | 中位 1.7 秒（0.4～2.5 秒） |
| 写回答复 | `deliveries.created − 模型结束` | 约 20 毫秒 |
| 页面看到答复 | 前端每 1.5 秒拉一次 `/api/state` | 平均多等 0.75 秒；接口本身 3～7 毫秒 |

结论：一句回复 4～11 秒里，模型只占 0.4～2.5 秒。大头是**每条消息现启动一个 Node 进程并加载 Pi 包**，在公司电脑上要 3～10 秒。

## 90 秒挂起

有一条消息的模型请求停在 `unknown`，持续 90.2 秒后整条接收超时失败。原因：SDK 的超时只限制每一次网络读，不限制整次调用，接收层也没有单次调用的时限，只有整轮 90 秒的外层上限。外层上限一到就直接失败，重试机制根本没机会起作用，用户看到的是笼统的“遇到问题”。

## 改法

1. 每次模型调用加硬时限：对话接收 20 秒，执行层沿用配置的超时。超时算作临时故障，按既有的 1 秒、4 秒退避重试；三次都不行，就告诉用户“模型服务没有正常回应”，并说明原话已保留。
2. 预先启动下一个 Pi 进程：服务启动时先拉起一个，加载完成后停在等待指令的状态；每次运行取走它，同时再拉起一个备用。进程照旧一次一用，预启动时不带任何任务数据，隔离方式不变。
3. 网页发来消息后立刻唤醒调度，不再等下一轮轮询。
4. 页面状态里加上每条消息的接收状态（已送达 / 正在读 / 已回复 / 失败），一次查询就能算出，不随历史条数增长。

5. 服务启动时，在后台线程里提前导入模型 SDK、加载证书库。

### 第 5 条是实测时发现的

改前改后各起一个全新服务，第一条消息都要 15～19 秒。拆开量：在本机导入一次 `openai` 包要 5～11 秒，原来这一步放在“第一次调模型”时才做，而且在事件循环里同步执行，这段时间整个服务都卡着。现在服务一启动就在后台线程预先导入。异步客户端本身仍在事件循环里创建，因为它和创建时所在的循环绑定。最初版本整体放进线程里创建，结果每次调用都连接失败，这个问题已经改掉。

## 改后实测

口径：本机分别起改前、改后两个全新服务，各用独立的空测试库、真实 DeepSeek flash 接口，每条消息间隔 3 秒，连发 6 条闲聊；从 POST 发出算起，到 `/api/state` 里出现新答复为止（脚本每 50 毫秒拉一次）。

| 指标 | 改前 | 改后 |
|---|---|---|
| 服务刚启动后的第一句 | 19.5 秒 | 6.0 秒 |
| 之后 5 句的中位数 | 2.9 秒 | 1.6 秒 |
| 6 句中最快 | 2.6 秒 | 0.7 秒 |
| 发出后页面显示“正在读” | 没有这个状态 | 0.03～0.05 秒（网页实测 0.24 秒，含前端轮询） |
| 模型一直不回应时，用户多久得到答复 | 约 90 秒，且只说“遇到问题” | 不超过 3 × 20 秒加 5 秒退避，并说明是模型服务没回应 |

公司电脑启动 Node 更慢（改前的账本里，启动这一步要 3～10 秒），所以那台机器上提速应该比上表更明显。这一点还需要用户在公司电脑上实际用一用才能确认。
