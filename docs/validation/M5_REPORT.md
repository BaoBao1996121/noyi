# M5：证据复盘、初步调优与完整自用交付

验收日期：2026-11-05（北京时间）。**M1–M5 全部计划范围已完成，交付 0.5.0 本地自用版**，不是只完成 M5 的独立页面。前阶段报告和证据保持原样；本报告记录最终增量、完整回归、真实调用及限制。

## 实现

- 显式发起复盘会冻结证据目录、观察窗口、指标、目标状态、近期工作成果和反馈。实验关联和普通历史复盘分开；没有实验时不套用“实验期未满”作为结论。历史快照已关闭，但不代表已经测得长期收益。
- 复盘证据受目标和用户边界约束，校验哈希；引用成果前必须完整读完全部页。操作回执 ID 与证据目录 ID 分开，运行时 schema 给出当前可引用 ID。存在工作成果时不能只读统计数字就交付；以前的模型复盘不循环充当新工作证据。
- 复盘保存观察、假设、未知、keep/stop/modify/insufficient 建议、引用及下一次检验条件。阶段性语句校验只针对已知的实验状态混淆，不声称通用语义判真。
- 正式复盘页和可下载报告的事实由冻结账本投影生成，模型建议单列。根任务数、后台协作者数、成果数、结构通过数各有含义；来源“连续失败为零”不代表历史从未失败。模型草稿保留并明确标注，不用它改写已确认计数。
- 观察计划保存假设、原方案、变化、指标、窗口、判定条件和不可变版本。采用下一次检验时间是明确用户操作；到期只发本地提醒、不调用模型。重启不重复提醒，停止观察后不再提醒，未自动改变任务权限或检查策略。
- 用户可对成果记录有用、遗漏或错误，以及催办、补充、纠错、接管等管理投入；耗时可留空，未知不填零。已填写耗时仅表示这部分用户报告，不能当成全部管理成本。
- 短而连贯的任务默认直接完成；真正需要分工时仍可协作。Windows Pi 取消/关闭释放全部管道句柄；新证据页计入新进展，重复读取不计。用户明确恢复会重新开始连续停滞窗口，累计消耗和失败历史保留。
- 完成后台启动/停止、设置、备份下载、新目录恢复、独立安装及数据隔离。恢复库未完成工作保持暂停，准入关闭，旧聊天与未完成投递不自动重发；恢复使用新的浏览器草稿空间。

## 真实 Qwen 对照

使用官网 `qwen3.7-plus`，执行前冻结协议、来源、预算、起始代码哈希和运行顺序：[比较协议](m5/comparison/protocol.json)、[原始结果](m5/comparison/results.json)、[汇总](m5/summary.json)。真实调用脚本为 `scripts/run-m5-eval.py`，需要显式提供本机模型凭据。

两组虚构文本任务：活动清单和未参与前期调整的读书会留出场景。每组比较单体、两位独立并行协作者、分工协作，再分别开关 Nudge，共 12 次。各组同模型、同来源权限与全队上限：32 次模型调用、90 次工具调用、900 秒、最多 2 位协作者；没有给每位协作者另发一整份总额度。

| 模式 | 运行数 | 平均模型调用 | 平均耗时 |
|---|---:|---:|---:|
| 单体 | 4 | 6.00 | 25.63 秒 |
| 独立并行 | 4 | 26.75 | 71.67 秒 |
| 分工协作 | 4 | 22.50 | 66.67 秒 |

12/12 通过明确的结构验收，共 **221 次真实调用、1,626,667 输入 / 35,601 输出 token**。这是每格一次的探索性小样本，部分运行与本机其他验证交错，耗时不是专门隔离的性能基准。不能推广为协作一般无益。

两组都包含真实缺失的可选资料；失败和披露记录保留。独立并行另出现一次错误指定自身为协作者、一次产物版本冲突，均保留失败工具操作和额外消耗。12 次 Nudge 自然触发均为 **0**，这只能说明开关对照已运行，不能证明 Nudge 有效或无效。留出来源约 6 KB，小于单页 8000 字符；真正跨页行为由独立协议测试验证，不把留出场景冒充跨页验收。

所有根成果由 Codex 对照冻结来源完整阅读，不是独立或盲评。现行人员、日期、作废要求、未知日期和没有新增审批总体匹配，但保留以下措辞问题：读书会单体把总负责人陈语推断为必须亲自提交复盘的人；另一份把“场地联络未分配且不得增派给陈语”写得像永久免责；一份协作成果的局部引文指向旧资料，虽然其他位置引用了现行资料。**不报告语义质量 100%。**

随后用 prompt 9 强调职责范围和直接执行，在同一读书会来源上再运行两次单体对照：[调优结果](m5/prompt9-tuning/results.json)。两次完成，共 **12 次调用、95,171 输入 / 2,302 输出 token**，但“负责人即亲自提交人”的更强推断仍出现，作为未解决的模型措辞风险保留，不能宣称提示调整已经消除。该批进程运行了新提示；当时第二处 manifest 的数字标签尚未同步，原始 prompt SHA/代码哈希保留，最终两个入口均使用版本 9。

本轮据此让短任务优先单体执行；重要职责和结论仍需用户核对。没有真实用户满意度、采纳率、完整人工管理时间或账单货币金额，均保持未知。

## 浏览器与真实复盘

实际浏览器完成成果反馈、观察计划创建、发起复盘、采用建议提醒时间、停止观察、预算增加/恢复、备份下载和正式报告下载：[UI 原始记录](m5/ui-review-evidence.json)、[浏览器检查](m5/m5-final-browser-evidence.json)。反馈明确写为 Codex 验收代测，不冒充用户长期反馈；耗时未填。

五项复盘分别使用 7、10、26、9、9 次调用，共 **61 次，780,760 输入 / 19,608 输出 token**。全部最终交付，但中间失败原样保留：

1. 第一份关联刚建立的观察窗口，证据不足，不编造实验效果；第二份改为历史记录，暴露原始字段和时间表达问题。
2. 第三份先在 14 次调用处用尽预算：已读取六类证据，却把 operation ID 当作 evidence ID，多次被拒绝。schema 加入可选证据 ID 后，明确加到 20 次仍因重新读证据被误判停滞。补充新证据页进展规则与明确恢复逻辑后，同一任务最终累计 **26 次**完成，没有重建任务洗掉失败和消耗。
3. 第四份仍借用了“观察期未满”语句，增加针对历史/实验状态的有限检查；第五份通过状态检查，但原始草稿仍把协作者计数误读成成果数，建议文本把当前零连续失败扩大成“从未失败”。因此正式报告改为冻结账本事实加单列模型解释，原稿没有删改。新的投影由协议测试、实际页面和下载哈希验证。

测试目标累计上限由用户操作路径明确从 40 增到 60、再到 80，没有自动加预算；M4 的 7 次旧调用与 M5 的 61 次复盘合计 68 次。目标最后已暂停，准入关闭，观察计划停止，不留自动计费验收任务。

正式报告清楚区分事实与模型判断，但单列的模型建议本身仍可能过度解释，用户需要核对。历史/实验阶段的语句规则是有限修复，不是语义正确性证明。

最终工作台、复盘和空白自用库截图均实际查看：[目标页](m5/m5-goal-final.png)、[正式复盘](m5/m5-review-final.png)、[自用首页](m5/m5-self-use.png)。同端口从验收库切换到日常库后，页面自动识别 workspace，旧草稿保留在旧库的浏览器空间，日常输入框为空，没有误发；新库 0 任务、0 目标、0 消息，Qwen 配置就绪。重新加载后的页面没有脚本错误或 HTTP 失败。历史控制台包含刻意重启时的断线、旧预算交互的两次 400、切库时旧房间请求的一次 400；均有恢复，不能声称整个测试历史零错误。

## 安装与备份恢复

另从 Git 暂存内容导出全新源码目录，实际运行 `scripts/install.ps1`，创建全新虚拟环境、按锁定版本安装 Python/Pi 依赖并成功退出。安装后依赖检查通过，实际 Pi 再完成 3 次可控协议调用、重开新增 0 次；独立端口上的启动、重复启动和正常停止全部通过：[源码安装证据](m5/m5-source-install-evidence.json)。没有复制个人密钥或验收数据库，也没有新增云模型调用。

从设置实际下载备份 ZIP，恢复到新目录并启动服务：SQLite integrity 为 ok；模型请求数 **64 → 64**，目标暂停、未完成任务暂停、准入 off、专用模型密钥不存在：[恢复证据](m5/m5-backup-restore-evidence.json)。不把缺失密钥的启动冒充真实模型请求。完整备份包含私人内容，不提交到 Git；恢复证据只提交去敏结果。外部原始文件不在备份内；管理目录内部路径会迁移。

日常入口为 `Start Personal Agent.cmd`，停止入口为 `Stop Personal Agent.cmd`，安装与操作见 [自用指南](../self-use-guide.md)。本机交付服务使用独立 `.pa/personal`，已配置官网模型；源码、安装包和备份不会携带专用密钥。
