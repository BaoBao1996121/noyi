# 回复层要不要开思考：三种答法对比评测（2026-11-17）

口径：只评测，不改产品行为。脚本 [scripts/eval-thinking.py](../../scripts/eval-thinking.py)，直接复用产品里的接收提示词、决定工具和草稿解析；题目原文、全部回答和抽查清单只存在本机不进 Git 的目录。

## 题目

自用库里用户真实发过的消息一共只有 22 条，其中约一半是「html 的吧」「行，就这样」这种接上文的短句，或者要联网查的（汇率、天气），不适合拿来比较答法。选了 9 条真实消息（闲聊 3、问助手能力 1、问产品事实 1 与模型 1、规划讨论 2、需要推理的问答 1），带上它们当时的前文；另补 13 条同领域的合成题，补上真实消息里缺的计算、方案对比和更多推理题。共 22 题。

| 类别 | 题数 | 去隐私的示例 |
|---|---|---|
| 闲聊 | 3 | 「在吗」「早上好」 |
| 问助手能力 | 1 | 「你能做啥」 |
| 简单事实 | 4 | 「1 大卡等于多少千焦」「现在用的是哪家的模型」 |
| 计算 | 4 | 给定身高体重步数，算每天该吃多少；一周进出热量算能瘦多少 |
| 推理 | 3 | 「天气和饮食有啥关联，从中医角度说」「为什么节食容易反弹」 |
| 规划 | 4 | 先聊记账小工具要哪些功能；排一周减脂晚餐 |
| 方案对比 | 3 | 轻断食和每天少吃一点哪个好坚持；数据存浏览器还是导出文件 |

每题注入和产品一样的上下文：当时的前文、自用库里已确认的记忆（约 1500 字）、Bot 角色、执行层能力清单。

## 三种答法

| 答法 | 做法 | 近似了什么 |
|---|---|---|
| A 现状 | 回复层 DeepSeek flash，思考关闭，强制调用决定工具，流式出字 | 与产品一致。回复层自己决定交给执行层的（44 次里 5 次），再接一次执行层回答，计入总时长 |
| B 回复层开思考 | 同 A，但思考开启（effort=medium） | DeepSeek 开思考时不接受强制工具，产品对此的处理是没拿到决定就追问一次，脚本照做 |
| C 先回执再细想 | A 的回复层先发一句回执，再由执行层开思考作答 | 执行层用一段精简的执行提示词，单轮、无工具、纯文本作答，代替产品里带工具、写文档、验收的完整执行循环。真实执行层更慢（多轮工具调用加验收），所以 C 的完成时间是下限 |

每题每种答法跑 2 次，共 44 组、真实 DeepSeek 调用约 150 次，并发 2，无失败。

## 质量盲评

评审用 Claude Opus 5.5（走本机评审网关，6 路并发）。同一题的 6 份回答打乱顺序，只标 R1～R6，四个维度各 1～5 分：正确、有用、条理、无编造，满分 20。评审能看到当时的时间、前文和助手可见的记忆，所以引用记忆、说「今天」不算编造。分两条发的回答按「第一条回执、第二条成果」原样展示。

第一轮评审没给时间，也没标出哪部分是回执，误扣了不少分。补上之后重评，下文用的是第二轮结果。

## 结果

### 总体

| | A 现状 | B 回复层开思考 | C 先回执再细想 |
|---|---|---|---|
| 首字（中位） | **0.94 秒** | 4.83 秒 | **0.94 秒**（回执） |
| 完整答复（中位 / 90 分位） | **2.6 / 6.5 秒** | 6.7 / 13.3 秒 | 8.6 / 10.9 秒 |
| 输出 token（均值） | 335 | 979 | 954 |
| 输入 token（均值） | 4476 | 8231 | 5681 |
| 质量总分（满分 20） | 16.7 | **17.1** | 15.4 |

### 按类别：质量总分 / 正确分 / 完整答复中位秒数

| 类别 | A | B | C |
|---|---|---|---|
| 闲聊 | 19.2 / 4.8 / 1.3 | 19.7 / 5.0 / 2.4 | 12.5 / 3.8 / 5.9 |
| 问能力 | 16.5 / 4.0 / 2.1 | 16.5 / 4.0 / 4.5 | 10.0 / 2.0 / 7.2 |
| 简单事实 | 17.0 / 4.0 / 1.5 | 16.1 / 4.0 / 3.7 | 14.6 / 4.3 / 4.5 |
| **计算** | **14.1 / 3.0** / 2.9 | **16.8 / 3.8** / 6.8 | 15.8 / 3.5 / 8.1 |
| 推理 | 16.7 / 4.3 / 3.3 | 17.2 / 4.7 / 9.6 | 17.2 / 4.2 / 10.9 |
| 规划 | 16.9 / 4.1 / 3.9 | 17.1 / 4.0 / 8.8 | 16.8 / 4.1 / 9.6 |
| 方案对比 | 17.0 / 4.2 / 2.8 | 16.5 / 4.3 / 9.3 | 17.0 / 4.2 / 9.8 |

读法：

- **计算题是不开思考唯一明显吃亏的类别。** A 的正确分是 3.0，B 是 3.8。不开思考的错误都是硬错：算出的摄入量达不到用户说的目标，基础代谢算错一百多千卡，第一句先给错数再自己改口。
- **推理、规划、方案对比三类，开不开思考差别很小**（总分差 0.5 分以内，评审的同题波动就有这么大）。不开思考的答复已经有条理，主要扣分点是个别说法过满。
- **闲聊、问能力、简单事实，开思考没有收益。** C 在这几类明显变差（闲聊 12.5 分）：一句问候被拆成「我想一想」加一大段汇报格式，还要多等 5 秒。

### 回复层直接开思考（B）有两个副作用

1. **多数轮次要调两次模型。** 开思考时 DeepSeek 不接受强制工具调用，44 轮里有 35 轮模型先写了一段普通文字，被追问一次后才调用决定工具。这是 B 首字中位到 4.8 秒、推理类到 7.9 秒的主要原因，输入 token 也几乎翻倍。
2. **追问的话会漏进答复。** 44 轮里有 7 轮开头写着「已记录」「登记清楚了」「答上了」这类话，评审判为编造动作（A 一次都没有）。来源是追问提示里「请用 resolve_conversation 记录你的答复」，模型把它当成用户在看的内容了。

所以 B 的总分虽然最高，但不能原样上线：等得最久，还会说没做过的事。

## 路由判断准不准

让回复层模型（flash，不开思考，JSON 输出）对每题判断「简单」还是「细想」，每题判 3 次，单次中位 0.81 秒。「这题需要细想」的标准：开思考的答法（B 或 C）平均比 A 高 1 分以上，或者 A 有一次正确分低于 3。

| | 实际需要细想 | 实际不需要 |
|---|---|---|
| 判成细想 | 9 | 2 |
| 判成简单 | 3 | 8 |

22 题里判对 17 题；3 次判断不一致的有 2 题。

- **判成简单、其实需要细想的 3 题**：一句早安（开思考只是没有多提一句前文，1 分差，属于评审波动）；问产品支不支持新开会话（不开思考的答复凭空断言「没有入口」，开思考的答复说明自己看不到界面。这题的问题是缺信息，不是想得不够）；先聊记账页功能（开思考答得更收敛，2 分差）。三题里只有最后一题算真的漏判。
- **判成细想、其实不需要的 2 题**：一周晚餐规划、两种减重方法对比。交出去只是多等约 6 秒，质量不降。
- **计算题 4 道里 3 道判成细想**，没判的一道（慢跑消耗）不开思考也答对了，所以 4 道都算判对。

判成细想的 11 题里，A / B / C 均分 15.7 / 17.1 / 16.8；判成简单的 11 题里是 17.6 / 17.2 / 14.0。按路由分流（简单的走 A，细想的走 C），这 22 题的均分是 17.2，与全走 B 的 17.1 持平；首字始终约 0.9 秒，B 是 4.8 秒。

## 结论和推荐

推荐方案 2：**回复层自动判断，难题先回执，再交给执行层细想。** 理由：

1. 质量差距集中在一类题上。只有计算题不开思考会给错数，其余类别差距在评审波动之内。所以没必要所有题都开思考，「保持现状」又会在算热量缺口这个主场景上算错。
2. 难题走「先回执再细想」，首字和现在一样是 0.9 秒，完整答复约 10 秒，质量与回复层直接开思考相当，而且没有 B 的两个副作用。这也正好是用户描述的体验：「先答应一下，然后去做」。
3. 回复层判断难不难，在这批题上对了 17/22。判错的代价不大：难题判成简单，大多数时候不开思考也答得差不多；简单题判成细想，只是多等几秒。
4. 没选方案 3（只把计算类交出去）：按题型写死要先认出题型，换一种说法就认不出来，属于对样例的规则。让模型判断「这题要不要多步计算或权衡」，机制上能覆盖相邻场景。

落地时要注意：

- 判断最好作为回复层决定里的一个字段，跟着现有那次调用一起出来，不另加一次 0.8 秒的调用。
- 交给执行层的回执要说清在做什么（如「我算一下你每天该吃多少」），不要用「我想一想」这种空话。闲聊、简单事实绝不能走这条路，C 在这些题上掉到 12～15 分就是这个原因。
- 交出去的问答题，执行层应直接回文字答复，不走写文档、验收的完整流程，否则完成时间会远超 10 秒。这一点需要单独设计。

## 局限

- 样本小：22 题，每题 2 次，其中 13 题是合成题。差 1 分以内的结论都不可靠，可靠的只有「计算题不开思考会错」和「闲聊走回执会变差」。
- 只用一个评审模型、一次评审。同一答法的两次回答，得分有时差 2～3 分，这里面既有回答本身的波动，也有评审的波动。
- C 的执行层是近似实现（单轮、无工具），真实执行层更慢；质量也可能因为带验收而更高或更啰嗦，需要真改了之后再测一次。
- 不含要联网的题，因为评测不碰搜索。
- 用户人工抽查清单（15 题，不标答法）已生成在本机，抽查结果还没回来，回来后补进这里。
