# 0.6.0：直接交办与内部跟进验收

日期：2026-11-05。模型沿用 Qwen 官网 `qwen3.7-plus`，执行循环沿用 Pi 1.5.0。

## 本次纠正

0.5.0 完成了 M1–M5 的底层功能和当时的测试，但把目标、计划、触发器和预算作为需要用户配置的工作流暴露出来。这不符合“像交代同事一样说需求，由助理负责实现”的产品要求。旧阶段报告保留为技术验收历史，不再把它们当成自然交办体验已完成的证明。

0.6.0 采用统一输入框。闲聊、新工作、补充、回答问题、暂停、继续、查询和持续跟进由系统接待并调用原有执行账本；不要求选择模式或填写目标表单。“正在跟进”只作为可选的进展与结果页。执行、权限、用量、成果验收和持久记录仍然存在于内部。

## 验证方式

- 协议测试使用实际 Node/Pi 循环与可控模型，覆盖版本、来源、nonce、跨重启次数、繁忙时控制、明确授权、记忆边界和恢复。它们不是云模型理解能力的成绩。
- 真实模型测试走与 WebUI 相同的 `/api/messages` 默认入口，无手动 mode/Goal/policy 设置。使用虚构读书会资料和独立验收库，不向外部发送消息，不污染日常资料库。
- 每轮真实测试保留原始数据库、步骤、工具失败和产物。仓库中的脱敏证据见 [conversation](conversation/manifest.json)，失败轮不从成本或结果中删除。
- 浏览器验证与独立 wheel 安装验证单列，不以 HTTP 或模拟界面代替实际浏览器，也不以 0.5.0 安装成绩代替新版验证。

## 修复中保留的失败

1. 第一轮共 23 次真实请求。资料整理与两句话改写完成；接待没有正确沿用“这份原始资料”的来源，建立了空来源任务，执行端重新索要已经给过的资料。修复为提供安全来源描述；明确指代且来源唯一时沿用原授权，多套可能来源则自然澄清。原始资料指代会排除派生报告。
2. 第二轮共 24 次真实请求。来源已正确继承，但“仅资料变化时处理”被模型错误映射为定时执行；同时“不用每次问我”被授权守卫误判成拒绝持续跟进。保留错误回执与多次失败。修复了确认/通知条件的否定范围、工具说明，以及仅变化处理必须使用来源变化观察的限制。
3. 第三轮先在第 17 次请求后停下：模型正确引用原始任务，程序却把原任务与其改写任务误判成不同资料，迫使模型重复澄清。修复按实际授权来源集合判断等价，仍区分不同资料和固定版本；保留失败快照，在同一隔离库仅重试受影响的后半段，最终完成协议序列，累计 45 次请求。没有为了改善数字而重算前面的调用。
4. 浏览器第一次自然复盘请求又使用 4 次接待调用，模型仅输出未登记文本，没有启动复盘工作。此轮明确失败。修复专门的复盘接待动作，让实际复盘 Task 直接承担原用户请求并接受成果验收；Qwen 接待阶段强制选择唯一的接待协议工具，普通业务工具仍保持原选择方式。
5. 全量回归发现旧的合法临时协作者交接不应自动获得持续安排权限，也不能因此使正常任务上下文报错。修复按当前身份提供工具与上下文，执行时仍检查权限。重复取消时的 Pi 子进程与管道回收也补了真实进程回归。
6. 独立审查修复了旧记忆从跟进/回顾上下文回流、恢复备份漏迁移待接待消息的状态和来源，以及繁忙接待阻塞明确暂停的缺口。浏览器还发现内部调度请求被显示成用户气泡，已按真实来源展示，账本原文保留。
7. 一份自动汇总在计划已改成十分钟后仍沿用旧职责中的“五秒”措辞，实际调度记录为 600 秒。旧文案保留；当前安排与带时间的历史处理摘要分开展示，并加强当前注册安排优先的提示。此类语义偏差不能靠结构验收保证完全消除。

## 实际边界

本版面向本机文本资料整理、变化/周期跟进和证据回顾。未连接邮箱、外部日历、通用电脑操作，未实现单次定时提醒。上传文件是副本；观察原文件需要用户明确提供完整路径或文本网址。关机或停止本机服务期间不会执行。

明确且无歧义的独立暂停/取消短句可绕过模型直接登记控制；其他自然表达仍需要接待模型判断，可能等待或澄清。接待每条输入跨重启最多 4 次模型调用，另计入持久模型账本；它不混同于某个持续事项的业务执行次数。

安排回执仅证明安排真实生效，不能替代用户同时要求的报告。回顾开始不等于回顾完成，观察计划不等于实验效果。产物验收和少量真实场景通过不保证所有自然语言理解、事实判断或长期效果；多日稳定性仍需自用反馈。
