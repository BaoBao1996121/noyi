# M2 验收记录

2026-11-04。实现和本轮代表性验收已完成；后续仍需 M3、M4、M5，不能把这里当作最终交付。

## 已实现

- 活动、失败、真实新增证据、预算分账。首次观察/负面证据、责任变化、已验收成果进入进展表；重复读取、任意改稿或只写假设不自动算新进展。连续 20 次失败，或已有成功观察后的 20 次重复无进展操作，会暂停并保留记录。
- 有界 Nudge 使用真实 Pi `finishTurn` 继续机制，不另写模型/工具循环；全队共用提醒与调用预算，不能因提醒重置。若子任务尚在运行或等待用户，结束门禁转为持久等待，零模型空转。新 WebUI/CLI 任务默认启用；旧 TaskSpec 未设置开关时保留原行为，便于升级和对照。
- 调查记录关联本任务操作证据；压缩保留当前要求、输入责任、否定证据、调查、评审、预算与完整工具调用组。历史正文仍可从受限读取工具取得。
- 原任务交接保留要求、所有权历史、责任代次、调查和预算；旧 Run 不能提交。子任务返工保留同一 task ID 和历史版本；开启 review_workers 后，所需子任务必须由父级明确复核。
- 依赖只有在父级接受前置成果后才启动；Worker 通过受限 read_dependency 读取当前已接受版本。上游返工后旧依赖证据不能通过完成门禁。
- write_artifact 的 base_version 冲突被拒绝，文件从不覆盖；新版本与原运行/要求版本入账。提交旧头版本或旧要求版本不能绕过验收。M0/M1 的已存文件版本可增量迁移，同 nonce 重放兼容新增的默认 TaskSpec 字段。

模拟对端只证明协议和状态，不作为模型能力收益。DS12 外部写入对账不适用：当前仍无远端副作用工具，不因阶段名增加外部发布能力。

## 真实 Qwen 与质量复核

[完整对照摘要](m2/summary.json)，每次请求、失败操作、进展、评审和全部产物版本均保留。初次三项任务使用同一官网 `qwen3.7-plus`：

| 任务 | 全队调用 | 输入/输出 tokens | 结果 |
|---|---:|---:|---|
| Nudge 关闭 | 5 | 19,709 / 737 | 机械检查通过；人工发现额外添加负责人审批，语义质量失败，保留原稿 |
| Nudge 开启 | 4 | 15,225 / 515 | 机械检查通过；本次没有触发 Nudge |
| 同 Worker 审核返工 | 19 | 97,624 / 2,491 | 一个子任务、至少两次执行；缺项首稿→明确返工→新版→父级接受→根成果 |

发现额外审批后，补充“原文义务与建议分开、不添加审批/负责人/日期”的通用约束，并说明文件名使用 ASCII。按同样模型、资料、权限和总预算重跑两组对照，不能只重跑失败组后拼接比较：

| 修正后任务 | 调用 | 输入/输出 tokens | 结果 |
|---|---:|---:|---|
| Nudge 关闭 | 4 | 15,473 / 508 | 核对单通过本轮主要要求和责任边界复核 |
| Nudge 开启 | 4 | 15,511 / 529 | 核对单通过本轮主要要求和责任边界复核 |

两个修正后试次仍都未触发 Nudge，因此**没有实测 Nudge 的增量收益**。每组只有一次真实试次，不作统计结论。精确的有无提醒差异由可控协议对端验证。各次失败和额外修正调用均计入总记录；提供方账单不可得，未编造人民币费用。

首选资料真实不存在，所有对应稿均披露 UNAVAILABLE [first]；另一已授权资料完成真实读取。审核返工任务的最终稿与原文逐项核对：负责人小林、首次检查截止日期2026-11-06、作者自查、独立复核、每周三复查、保存原版本、未复核只能草稿。初稿和返工稿不覆盖，不以新建子任务隐藏缺项。

## 限制

机械检查仍不等于完整语义事实核查；本次失败证明了这一点。修正后有常规解释性措辞，不能当作逐字原文或新增制度。压缩后的模型成本尚未在相同工作量下完成稳定对照；与 M1 数字不同不能称为节省比例。源码哈希分为导出树和修正后试次启动时快照，保持两者区别。M5 继续做总体对照、管理成本和自用调优。
