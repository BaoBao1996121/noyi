## 实现与协议验收

- `tests/test_m1_store.py`：B01–B14、派生授权范围、DS04/05/08/10。
- `tests/test_m1_scenarios.py`：真实 Pi 多 Worker 汇总、B15 同伴声称授权不扩权、DS06/07/09/11、持久问题重开、旧要求成果复核、停止过程中继续、context 订阅、共享时间预算与替换契约。
- 既有 M0 协议测试继续运行。测试模型是可控协议对端，不能当作 Qwen 效果评测。

旧成果保留原要求版本；在新要求下只有读取已验收文件、校验哈希、记录具体复核理由后才可采用。收到输入、进入模型请求、处理完责任分别记录；读取不等于落实。控制先落盘，执行器和 Node 子进程退出后才确认停止。并发默认 3，硬上限 4，同一 actor 仍只允许一个实际执行槽位。

## 真实官网闭环

原始摘要和复核数据：[evidence.json](m1/evidence.json)。总任务 `14031492e6f0413c9ced4c9a68cf285f`，官网 `qwen3.7-plus`。

1. 输入两份短资料，要求分别委派核对发布流程与例外边界。
2. 总控进入等待后停止回复；两位 Worker 仍成功完成。
3. 关闭并重开账本，追加明确生效日期的要求。总控读取两份原文与两份成果，为两份旧版本成果分别记录复核，处理补充责任并交付。
4. [最终清单](m1/14031492e6f0413c9ced4c9a68cf285f.md) 包含适用范围、例外、行动清单、来源引用与 2026-11-05 生效日期；已人工逐项对照留存的两个输入，未发现漏掉必需发布复核或错误扩大例外。
5. 重开、同 nonce 重复提交、再启动服务，tasks/runs/messages/events/operations/model_requests/deliveries 计数不变，新增模型调用 0。

全队 21 次模型请求，输入 121,575 tokens、输出 3,991 tokens；未取得提供方账单，费用不编估计。请求和 Worker 成本均计入根预算。该任务验证来源核对与交付，不证明任意语义质量，也不等于多日稳定性。

## 修正与边界

测试发现并修正过：补充后旧成果无法采用、恢复时已读未处理补充丢失、停止清理阶段收到继续却被覆盖、上下文订阅误唤醒、实际执行器清理与数据库槽位释放之间的窗口、慢投递漏掉末批结果。新增时间预算检查曾影响直接 Runtime 超时和恢复计数；已通过针对性回归修复。问题问答用例曾有 JSON 转义断言错误，已改为检查解码后的值。

本阶段最终验证为 Python 149 项、Node 11 项。真实任务完成后补强了全队运行中时间预算检查，相关故障回归另行通过；证据中的源码哈希是导出时的验证树，不伪称为所有先前调用加载时的源码快照。

模型上下文目前偏大，21 次调用用了约 12 万输入 tokens；M2/M5 将保留证据而压缩重复上下文，并比较预算及结果。完整审核返工、产物版本、长期 Bot/记忆、真实触发、复盘和 WebUI 分别在后续阶段，不由本报告宣称完成。
