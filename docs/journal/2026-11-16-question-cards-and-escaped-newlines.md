# 对话页：结束的问题卡片回到历史里，回复里不再出现字面「\n」

- 日期：2026-11-16
- 类型：修复
- 相关提交：（见本篇所在提交）

## 问题

用户在对话页看到两个问题：

1. 两张早已结束的「问题记录」卡片（一张已回答，一张显示「此问题已失效」）一直钉在对话最底下。用户新发的消息和助理的回复反而排在它们上面，看起来像对话停在了旧问题上。
2. 一条助理回复里直接显示出「\n\n1.」这样的字面转义，列表没有换行。

## 前后对比

| 指标 | 改前 | 改后 |
|---|---|---|
| 最底部显示的内容 | 两张 9 天前的旧问题卡片 | 最新一条助理回复 |
| 已结束问题的位置 | 全部堆在所有消息之后 | 回到提问当时的位置，样式变淡、虚线边框、带时间 |
| 自用库 24 条回复中显示字面 \n 的 | 1 条 | 0 条（库里原样未改，读取时还原） |

桌面和手机宽度下都用自用库副本在浏览器里实测过。

## 怎么做的

**卡片位置。** 根因在前端：对话页把所有问题卡片统一拼在全部消息之后，既不看时间也不看状态；接口返回的问题也没带创建时间。修法是让问题跟消息一样有时间，并抽出一条通用规则：已回答或已失效的问题按创建时间放回历史；只有还在等回答的问题留在最底部，方便直接作答。这条规则对所有问题卡片都成立，不针对哪一张。数据库没动。

**字面 \n。** 逐层排查：模型返回的工具调用参数原文里就是 `\\n`，也就是模型把换行多转义了一层。JSON 解码和存库都没错，前端也只是如实显示。所以在模型文字进入账本的入口处统一还原：回复、通知、问题和选项都走同一个函数。已存进库的旧数据，在读取接口里用同一个函数还原，不改库。

判定规则是通用的，只在「确定是多转义了一层」时才还原，避免误伤本来就该显示字面 `\n` 的内容：

- 文本里已经有真实换行的，不动；
- 代码块和行内代码里的内容，不动；
- 代码之外只要出现一个不是合法 JSON 转义的反斜杠（比如 Windows 路径里的 `\U`），就判定这不是编码后的文本，整段不动；
- 只有满足以上条件，才把代码之外的部分解码一层。

比较过的方案：在前端渲染时替换 `\n`。没选它，因为它只修了一个显示位置，手机推送、回放、交接给执行层的对话仍然会带着错误文字；而且前端无法区分代码里的字面 `\n`。

## 没做到 / 边界

- 交付成果文件本身（模型写的 markdown 或 HTML）不经过这个还原。检查了自用库里所有成果和摘要，换行都是真实的，没有这类问题。
- 如果模型输出的整段文字既没有真实换行、又是在讲转义字符本身，而且没用代码格式包起来，会被还原成换行。概率低，而且显示上只是多了个换行。
- 手机端的离线缓存版本号升了一级，让手机拿到新样式。

## 写文章可用的点

「多转义一层」看起来像渲染问题，实际是模型在工具调用参数里的输出习惯。修在入口处，所有显示位置一起好；判定规则要写成「能证明它是编码文本」才动手，而不是看到 `\n` 就替换。
