# 难题先答应、再细想：回复层自己判断要不要想

- 日期：2026-11-17
- 类型：功能 + 修复
- 相关提交：（见本篇所在提交）

## 问题

上午的对比评测（[thinking-mode-eval.md](../validation/thinking-mode-eval.md)）显示，回复层不开思考只在计算类题上明显吃亏：算出的摄入量达不到用户自己定的目标，或者基础代谢算错一百多千卡。全部开思考，首字要等将近 5 秒，还会冒出「已记录」这类没做过的事。用户的要求是：「像一个可靠的助手一样，我说个任务，他会先答应一下，然后去做」，并且「按推荐做」：由回复层自己判断难度，难题先回执，再交给执行层开思考作答。

## 前后对比

同一份评测脚本、同 22 题、每题 2 次。改前的答复（A）和改后的答复（N）放在一起打乱，由 Claude Opus 5.5 盲评，满分 20。

| 指标 | 改前 | 改后 |
|---|---|---|
| 全部题均分 | 16.6 | **17.3** |
| 难题均分（12 题，上午评测认定需要细想的） | 16.0 | **17.4** |
| 难题正确分（满分 5） | 3.8 | 4.1 |
| 首字中位（全部 / 难题） | 0.94 / 0.87 秒 | 0.99 / 1.01 秒 |
| 被交出去细想的难题，完整答复中位 / 90 分位 | 改前不存在这条路 | 9.1 / 11.4 秒 |
| 当场答的题，完整答复中位 | 1.8 秒 | 1.9 秒 |
| 路由准确率（判断要不要细想） | 单独测 17/22 | 跟着决定一起出，15/22 |
| 答复开头出现「已记录 / 登记」等没做过的事 | 回复层开思考时 7/44 | 0/44 |

按类别看，计算、方案对比、问能力三类提升最大（总分分别为 14.9→17.0、16.2→18.3、14.5→17.5）。闲聊持平（18.0 / 18.0），只有简单事实一类降了 1.5 分。逐题看，这一类的下降来自一份回答把鸡胸肉生熟换算的方向说反了。它属于当场答的一次波动，和这次改动的路径无关：这道题两次都判成简单，走的是和改前一样的当场答。

回执现在说清在算什么，例如「我按 30 岁男性、175 厘米、80 公斤、每天 8000 步，算基础代谢、日常消耗和一个月瘦 2 公斤对应的每日热量。」不再是空的「收到」。

## 怎么做的

- **难度由模型判断，做成现有决定里的一个取值。** 回复层本来每条消息都要调用一次决定工具，现在它多了一种接法：`new_task` 加上 `result_kind=answer`，意思是「这道题要细想，交给执行层答」。提示词描述的是「什么样的答案需要细想」，即多步计算、要权衡几个因素或方案、有几部分的计划，而不是题目类别或关键词。所以换一种说法、换一个相邻领域，判断依据照样成立。判断跟着已有的那次调用一起出来，没有多一次模型调用，首字时间基本不变。
- **执行层对问答题走轻路径。** 这类任务只给执行层两个工具：「发送答复」和「做不到」。提示词要求开思考算清楚、先给结论、写明假设，不能声称查过或记录过什么。不写文档，也不走文档验收。执行层本来就按配置开思考（effort=medium），所以这条路不用改模型设置。
- **承诺规则照旧。** 回执登记成承诺，跟着任务走；答复本身就是这次的交付。只有答复真正送达用户，承诺才算兑现，兑现记录里引用这次「发送答复」操作和送达的消息。答复里如果又答应以后的事（「明天提醒你」），会被拒回，要求删掉这句再发，因为这条路登记不了任何安排。
- **DeepSeek 开思考时不接受强制工具调用。** 执行层偶尔会直接用普通文字写答案，这时运行时提醒它一次，用「发送答复」重发；第二次还是普通文字，就按「没拿出结果」处理。评测里 44 次没有一次需要提醒。
- **修掉追问提示词漏进答复的问题。** 根因是：回复层没拿到决定、要追问时，追问是以「用户」的身份说的「请用 resolve_conversation 记录你的答复」，模型就当成用户在要求它记录，答复开头写出「已记录」。现在追问一律作为系统说明发出，注明「不是用户说的，不要在答复里提」，并放在用户原话之前，用户原话仍然是最后一条。这对所有追问都生效，包括账本拒绝某个决定后的重问，不只针对这一句话。

## 没做到 / 边界

- 路由准确率 15/22，比上午单独测的 17/22 低一些。漏判的 5 题里，3 题是上午就漏的（问产品支不支持新开会话、先聊记账页功能、一句早安）；另外 2 题（晚上吃碳水会不会胖、记账数据存哪里）当场答也得了 17～18 分。两次判断不一致的有 3 题。判断可以再调，但这一版先这样，因为判错的代价是多等几秒或少想一层，不会答错类别。
- 交出去的难题完整答复约 9 秒，比当场答多 6～7 秒。中间用户能看到具体的回执，不是干等。
- 评测里执行层用的是和产品同一套提示词与工具，但没有走完整的服务、调度和送达。真实服务里的端到端时间，看下面的实测。
- 用户对上午 15 题的人工抽查还没回来。

## 写文章可用的点

「要不要细想」不必另起一次路由调用。让回复层在它本来就要做的那次决定里多给一个取值，判断就是免费的。另一个值得讲的是追问的身份：程序给模型的追问如果以用户的口吻说，模型会把它当成用户的话来回答。
