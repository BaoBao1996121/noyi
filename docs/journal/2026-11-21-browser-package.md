# Noyi 能自己开浏览器办事了，登录交给用户在手机上亲手做

- 日期：2026-11-21
- 类型：功能
- 相关提交：c47967f、8e522ad、56151a2、25dd7f2、ff26033、9f238b2、f993fd0、6308bd1、8a1b948（及本篇所在提交）

## 问题
用户希望 Noyi 能打开网页、点按钮、填表、读页面，遇到要登录的站就停下来交给用户自己登，登好后接着做，以后复用登录状态。两条不能动的约束：密码和验证码永远由用户亲手输入，Noyi 不经手；用单独的浏览器档案，不碰日常用的 Chrome。核心指标是快。

## 前后对比
同一套脚本、同一个模型（deepseek-flash，思考关闭），一组用 Noyi 的浏览器工具，一组用截图循环（动作后等 2 秒再截图），每站 5 次。下表是最终版（第三次验收）：

| 站 | 输入 token 中位数 Noyi / 截图 | 总耗时中位数 Noyi / 截图 | 答对 Noyi / 截图 |
|---|---|---|---|
| 必应搜版本号 | 20.5K / 28.7K | 9.4 s / 34.3 s | 5/5 / 4/5 |
| 填表提交 | 5.0K / 49.1K | 6.9 s / 57.8 s | 5/5 / 4/5 |
| 翻页数数 | 11.7K / 23.9K | 7.4 s / 28.2 s | 5/5 / 0/5 |

整链路（把任务当成用户的一句话交给 Noyi）：15 次全部交付、全部答对，每次总耗时中位数 19～23 秒。浏览器每次调用里 Noyi 自己的开销（扣掉网页自己的加载时间）中位数 683 ms，含网页加载是 959 ms。

三轮验收的变化：第一次 search 只交付 2/5、token 是截图组两倍；第二次交付 15/15、token 全面低于截图组，但含网页加载的调用中位数 1097 ms；第三次把门槛改成只算自身开销（原因见验收预登记），自身开销 683 ms。

## 怎么做的
- **能力包按需加载**：浏览器的 8 个工具平时不在工具清单里，模型调 `load_capability("browser")` 后才出现，追加在清单末尾，前面的声明和服务商的提示缓存不变。这是通用机制，以后别的大工具组也走它。
- **看网页用无障碍树快照，不用截图**：快照只给可交互元素编号，去掉无名包装层和装饰，网址截到 100 字；同一页变化不到六成只回增量；更早的快照在发给模型前换成占位，账本里保留原文。三站快照体积降了 25%～35%，模型上下文只留最新一份。
- **写操作先拦再问**：只有「提交类」动作（提交表单、点非链接按钮等）才开写窗口，窗口内所有非 GET 请求先拦下；表单提交在页面里拦（网络层中止会变错误页）。问用户时记下页面版本（网址、表单字段值、元素结构的哈希），确认后重做前再核一遍，页面变了就作废重问。确认只能用一次。
- **已知缺口照实标出**：用 GET 或 WebSocket 发出的写操作拦不住，结果里标 `unguarded`，测试证明这类操作永远不会被标成「已确认」。
- **密码不进任何记录**：密码、一次性验证码、信用卡号等字段在快照、正文、账本、文件里一律显示 `[secret]`，模型也不能往这类字段填值，只能调 `browser_login` 交给用户。
- **登录交接用实时画面**：电脑和手机打开同一个实时画面（CDP 截屏流，WebSocket 推帧，点击、输入、按键回传），不弹真窗口。画面入口要一张 60 秒、一次性的票，只在有待登录的问题时发，交接结束就断开，不记录画面。
- **只访问公网地址**：每个页面用 CDP 的请求拦截做地址检查，挡住内网和本机地址。
- **作答路线需要外部信息就转成普通任务**：接收层有时把「查个版本号」当成凭知识就能答的问题，交给没有工具的作答路线。现在作答路线每次交付都必须声明是否需要外部信息（结构化字段，不看回答文字）；声明需要，就在同一个任务、同一条消息、同一个承诺下转成普通任务继续，用户不会多收到一句话。声明不需要却在回答里说做不到的，这次交付会被退回。
- **新窗口改在任务标签打开**：必应的结果链接默认开新窗口，任务标签停在原页。页面注入脚本把 target 链接、表单和 window.open 都改到当前标签，漏网的弹窗也会被接回。
- **预备空白标签页**：每个新任务第一次开网页要多等约 1.5 秒建标签，现在提前备好一个。
- **等页面稳定只看主文档**：先等主文档加载完，再给 0.6 秒宽限（必应在 load 后约 0.46 秒自己跳转一次），DOM 不再变化的等待并行进行，中途换了文档就重来，最多 3 轮。试过等页面所有请求安静，结果被必应几十个脚本请求和统计请求拖住，自身开销涨到 1.7 秒，放弃了。
- **执行层先看能力包**：有一次执行层没看到浏览器工具就直接报做不到。提示里加了一句：判断做不到之前先看能力包。
- 试过又放弃的：上下文级请求拦截会关掉 HTTP 缓存，必应因此返回几乎空白的页面；必应搜索页会自己跳转一次，导致元素编号失效，后来给快照绑定文档编号，页面自己跳了就重取。

## 没做到 / 边界
- GET 和 WebSocket 发出的写操作拦不住（见上）。
- 真实登录交接（手机实时画面亲手登录）待和用户约时间做一次。
- 首次装机要下载约 100MB 的浏览器内核，下载失败时浏览器能力包自动隐藏，不影响其他功能。

## 写文章可用的点
给模型看网页，结构化快照加「只留最新一份」比截图省一半以上 token，而且答得更准；写操作的确认要绑定页面版本，否则用户确认的和实际执行的可能不是同一件事。
