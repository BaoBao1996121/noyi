- 类型：功能

## 问题
用户希望 Noyi 能打开网页、点按钮、填表、读页面，遇到要登录的站就停下来交给用户自己登，登好后接着做，以后复用登录状态。两条不能动的约束：密码和验证码永远由用户亲手输入，Noyi 不经手；用单独的浏览器档案，不碰日常用的 Chrome。核心指标是快。

## 怎么做的
- **能力包按需加载**：浏览器的 8 个工具平时不在工具清单里，模型调 `load_capability("browser")` 后才出现，追加在清单末尾，前面的声明和服务商的提示缓存不变。这是通用机制，以后别的大工具组也走它。
- **看网页用无障碍树快照，不用截图**：快照只给可交互元素编号，去掉无名包装层和装饰，网址截到 100 字；同一页变化不到六成只回增量；更早的快照在发给模型前换成占位，账本里保留原文。三站快照体积降了 25%～35%，模型上下文只留最新一份。
- **写操作先拦再问**：只有「提交类」动作（提交表单、点非链接按钮等）才开写窗口，窗口内所有非 GET 请求先拦下；表单提交在页面里拦（网络层中止会变错误页）。问用户时记下页面版本（网址、表单字段值、元素结构的哈希），确认后重做前再核一遍，页面变了就作废重问。确认只能用一次。
- **已知缺口照实标出**：用 GET 或 WebSocket 发出的写操作拦不住，结果里标 `unguarded`，测试证明这类操作永远不会被标成「已确认」。
- **密码不进任何记录**：密码、一次性验证码、信用卡号等字段在快照、正文、账本、文件里一律显示 `[secret]`，模型也不能往这类字段填值，只能调 `browser_login` 交给用户。
- **登录交接用实时画面**：电脑和手机打开同一个实时画面（CDP 截屏流，WebSocket 推帧，点击、输入、按键回传），不弹真窗口。画面入口要一张 60 秒、一次性的票，只在有待登录的问题时发，交接结束就断开，不记录画面。
- **只访问公网地址**：每个页面用 CDP 的请求拦截做地址检查，挡住内网和本机地址。
- 试过又放弃的：上下文级请求拦截会关掉 HTTP 缓存，必应因此返回几乎空白的页面；必应搜索页会自己跳转一次，导致元素编号失效，后来给快照绑定文档编号，页面自己跳了就重取。

## 没做到 / 边界
- GET 和 WebSocket 发出的写操作拦不住（见上）。
- 真实登录交接（手机实时画面亲手登录）待和用户约时间做一次。
- 首次装机要下载约 100MB 的浏览器内核，下载失败时浏览器能力包自动隐藏，不影响其他功能。

## 写文章可用的点
给模型看网页，结构化快照加「只留最新一份」比截图省一半以上 token，而且答得更准；写操作的确认要绑定页面版本，否则用户确认的和实际执行的可能不是同一件事。
