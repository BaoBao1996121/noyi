# 家里部署：逐条清单，安装脚本自动去掉计划任务的 3 天时限

- 日期：2026-11-17
- 类型：修复（部署）
- 相关提交：92e148c（清单），本篇所在提交（安装脚本）

## 问题
用户要在家里电脑上从零装 Noyi，希望把步骤放进仓库，拉下来照着执行。原来的部署说明偏讲原理，有几处和脚本的实际行为对不上。写清单时对照脚本，又发现一个会让服务悄悄停掉的默认设置。

## 前后对比

| 项 | 改前 | 改后 |
|---|---|---|
| 计划任务运行时限 | `schtasks /Create` 默认 72 小时（`PT72H`），守护进程跑满 3 天被系统停掉，要等下次开机才会再起来 | 安装脚本建完任务后改成不限（`PT0S`）并读回核对，改不掉就报错 |
| 电池 | 默认用电池时不启动、切到电池就停 | 两项都关掉 |
| Tailscale 重启后 | 文档没写，不登录桌面时手机连不上 | 安装结束时提示开启无人值守，清单里有这一步 |
| 部署步骤 | 一篇原理说明 | 逐条清单：每步写清怎么确认成功、失败怎么办，要用户亲手做的单独标出 |

验证：在本机用和脚本相同的 `schtasks /Create` 建了一个临时任务，改前读到 `PT72H True True`，执行修正代码后读到 `PT0S False False`，随后删掉了这个任务。安装脚本过了 PowerShell 语法解析。整套安装还没在家里电脑上实际跑过。

## 怎么做的
- 根因：`schtasks` 命令行不能设运行时限和电池选项，所以用它建出来的任务全都带着系统默认值。修法放在建任务的那一处，三个任务统一处理，而不是只给守护任务加特判。修完读回设置核对，避免「以为改了其实没改」。
- 清单还纠正了原说明和代码不一致的几处：页面上没有停止按钮，改成调接口的命令；`hold` 文件只能阻止守护进程再次启动，停不掉正在跑的服务；用 PowerShell 5 写的设置文件开头会多出 BOM，脚本会读成空设置，清单改用不带 BOM 的写法。

## 没做到 / 边界
- 计划任务、S4U、开机自启、Tailscale 下的推送，都要等家里实测才算验证过。
- 首次安装失败的版本会进失败名单、不再重试，目前只在清单里给了手动移出的命令，脚本没改。

## 写文章可用的点
命令行建出来的任务会悄悄带上「3 天后停止」这个默认值，常驻服务只在第四天才出问题。写成逐条清单、每步都要核对实际状态，才把它查了出来。
